# Production tool adapters: proposed integration contract

**No production adapters are implemented in this release.** The included Python CLI performs local evidence checks. It does not call media models, renderers, editors, storage providers, review services or publishing APIs. The workflow skill can guide a human or assistant using independently available, authorized tools.

A future adapter should implement a small explicit boundary, not hide provider actions behind an automatic workflow step:

1. `capabilities()` reports supported media, limits, dependencies and whether work is local or external. Report configured availability separately from tested successful execution.
2. `preflight(request)` validates inputs, rights/use bounds, requested operation, destination, expected cost and permission requirements without generating or uploading. Return an explicit unsupported result rather than silently substituting a provider or model.
3. `execute(approved_request)` performs only the exact approved scope and returns operation identity plus state (`pending`, `succeeded`, `failed`, `unknown`). An approval token is an application-owned control, never a secret bundled into a project artifact.
4. `status(operation_id)` resolves pending or unknown results before retry. Define idempotency behavior and cost implications; do not assume every provider supports cancellation or safe retries.
5. `collect(operation_id)` retrieves authorized outputs into a project-owned staging area, checks hashes and stores a sanitized receipt. Output retrieval is not independent artistic review.

## Request information

Use project-relative asset references, exact input hashes, operation type, explicit tool/model choice, settings, output expectations, allowed data destination, maximum incremental cost and the caller's scope reference. Keep secrets in the host's approved credential mechanism, never in JSON examples, receipts, command-line arguments or version control. Input paths and returned output paths must pass containment checks.

## Result information

Return the actual provider status, operation identity, sanitized configuration, measured cost when available, errors, output paths/hashes and unknown fields. Do not invent successful execution, listening, artistic scores or reviewer independence. Local execution evidence and independent review evidence are different records.

## Candidate adapter categories

- Asset creation or editing: preserve originals and record derivation, rights and approved model selection.
- Timeline/editor/renderer: use frozen project and asset versions; supply preview and master exports with technical metadata.
- Sound and alignment: separate synthetic speech generation, timing estimation, mixing and actual listening review.
- Reviewer: supply frozen accessible media and return concrete observations, limitations and rubric findings. Reviewer count and independence remain project requirements, not labels generated by the adapter.
- Storage/delivery: require explicit destination and audience permission; read back the saved item. Publication needs its own authorization.

These categories are extension points, not compatibility claims. Implementers must add provider-specific tests, permission/cost checks and operational documentation before marking an adapter usable. A generic local evidence pass must never authorize the adapter to act.
