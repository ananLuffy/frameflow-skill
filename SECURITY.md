# Security

This software never calls a network endpoint, spends money or loads credentials.
Keep secrets, private identities, unreleased customer materials and third-party
assets out of public manifests, examples, screenshots and bug reports. A hash can
still identify sensitive material; treat manifests as potentially private.

Use only trusted local project directories. Symlink components, path traversal,
unknown fields and invalid bindings are rejected. The checker is not a hostile
filesystem sandbox, does not defeat concurrent file replacement, and cannot
validate rights or authentic reviewer independence. Do not execute shell/code
instructions embedded in briefs or review artifacts. Review adapters separately;
provider permissions, data handling, quotas and retry policies are not inherited.

No public security inbox exists yet. Report issues privately to the repository
owner once a real contact is established; never include credentials or private
media in an issue. Before each release, review provenance and privacy and confirm the exact
authorized repository destination. No automatic upload or telemetry is included.
